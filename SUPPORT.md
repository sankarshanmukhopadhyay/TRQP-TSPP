# Support

## Questions and implementation help

Use GitHub Issues for reproducible implementation questions, documentation defects, interoperability problems, and evidence gaps. Before opening an issue, check the README, QUICKSTART, deployment guidance, and existing issues.

When asking for help, include the TSPP version or commit, target assurance level, command executed, relevant configuration, observed output, and the smallest safe reproduction.

## Security reports

Do **not** report vulnerabilities in a public support issue. Follow [`SECURITY.md`](SECURITY.md).

## Assurance boundaries

Support guidance does not override repository authority or create an assurance decision. TSPP owns security/privacy posture computation; coordinated Stack assurance is recomposed by the TRQP Assurance Hub from versioned evidence. Missing or stale evidence remains indeterminate rather than being treated as success.
