# TIS Posture Evidence Contract

TRQP-TSPP v0.14.0 maps security and privacy posture evidence to Trust Infrastructure Schemas v0.10.0 artifact roles without making TIS a runtime dependency.

TSPP remains responsible for posture computation. It evaluates metadata, freshness, context allowlisting, rate limits, signed responses, lifecycle publication, relying-party publication, supply chain integrity, and higher-assurance governance evidence. TIS provides portable artifact contracts for downstream assurance publication and audit.

## Contract mapping

| TSPP output | TIS artifact role | Purpose |
|---|---|---|
| `tspp_posture_report.json` | assurance evidence | Records posture outcomes, assurance level, target, run, and control satisfaction |
| `control_satisfaction` summary | control assurance matrix input | Maps checks to control coverage and residual gaps |
| `lifecycle_publication` metadata | status or revocation evidence | Records status feed URI, supported lifecycle states, revocation support, and SLA |
| relying-party publication artifact | registry/public assurance publication input | Records public-facing limitations, validity, revocation guidance, and redress metadata |
| posture bundle descriptor | evidence bundle manifest input | Provides artifact index and integrity references |

## Authority, delegation, and scope

TSPP does not create ecosystem authority. It evaluates whether the declared registry or trust service posture satisfies selected profile expectations.

| Surface | Scope meaning |
|---|---|
| `run_id` | Shared execution identity for a combined assurance run |
| `target_id` | Stable identifier for the evaluated implementation or service |
| `assurance_level` | Profile level used to evaluate posture |
| `control_satisfaction` | Evidence of what checks were evaluated, passed, failed, skipped, or not applicable |
| `lifecycle_publication` | Evidence that relying parties can discover status and revocation changes |

The Assurance Hub binds these fields to a Combined Assurance Manifest and public assurance summary.

## TIS projection metadata

Posture evidence bundle descriptors MAY include:

```json
{
  "tis_projection": {
    "tis_version": "v0.10.0",
    "assurance_schema": "trust-infrastructure-schemas/assurance/assurance.schema.json",
    "control_matrix_schema": "trust-infrastructure-schemas/controls/mappings/control-assurance-matrix.schema.json",
    "decision_receipt_schema": "trust-infrastructure-schemas/decision/decision-receipt.schema.json",
    "status_or_revocation_schema": "trust-infrastructure-schemas/profiles/vti/status-list-reference.schema.json",
    "projected_artifacts": [
      {
        "source_artifact": "tspp_posture_report.json",
        "tis_role": "assurance-evidence"
      }
    ]
  }
}
```

## Enforcement and revocation

TSPP checks whether enforcement-related posture evidence exists. It does not itself enforce relying-party behavior. Enforcement and revocation should be interpreted through:

- status feed publication;
- revocation support declaration;
- publication SLA;
- signed response posture;
- relying-party publication guidance;
- Hub lifecycle and public assurance summary fields.

At AL3 and AL4, missing lifecycle or revocation evidence should be treated as a material assurance limitation.

## Audit evidence

For audit-ready posture evidence, preserve:

- posture report;
- posture evidence bundle descriptor;
- checksums;
- control satisfaction summary;
- lifecycle/status publication evidence;
- relying-party publication artifact where available;
- supply chain integrity artifacts for AL3+;
- public assurance summary generated by the Hub.
